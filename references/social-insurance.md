# 社保增减员、缴费与定时任务

v0.2 流程支持，核查日期 2026-10-27。当前尚无任何城市的真实账户接入或缴费验收。不要将本文当成全国统一操作入口、扣款时间表或社保费率表。

## 先识别实际业务

只收集当前需要的信息，优先用用户已有材料：

1. 个体户登记名称、实际参保/缴费城市、单位参保登记是否完成；不能从聊天所在项目猜主体。
2. 是雇员的单位参保，还是经营者本人灵活就业参保，或两种都有。灵活就业人员不能机械套用“单位增减员”。
3. 本次是增员、减员、变更基数、核对账单、签约代扣、查询扣费结果还是创建周期任务。
4. 经营地、税务登记地和参保地可能不同；以实际登记和办理要求为准。

先看当地税务、人社/医保部门官方说明与登录后的实际页面，确定经办机构、分工、办理截止日、生效月份、缴费基数口径和补缴要求。没有核实前不自动套用某省的规则或把全部险种都归为一个入口。

全国依据：[中华人民共和国社会保险法（2018 年修正）](https://www.samr.gov.cn/zw/zfxxgk/fdzdgknr/bgt/art/2023/art_e81d115419b4463ebb59ec46467fb136.html)，第 10、23、57、58、60 条区分单位/个人参保及登记缴费责任。具体操作、费率、期限和银行代扣安排仍需当期当地依据。

## 增员与减员

按用户实际请求制作变更清单，再操作，不在首次资料询问时索取全体人员完整身份证件。

| 增员资料 | 减员资料 |
| --- | --- |
| 人员私有编号/姓名、实际入职日 | 人员私有编号/姓名、实际离职/解除日期与原因 |
| 需参保险种、当地要求的工资或缴费基数资料 | 当前参保险种与状态、申请停保生效月份 |
| 既有参保/转入状态、当地要求的办理材料 | 当期已申报/已缴费情况，必要的解除/终止依据 |
| 申请起保月份及官方口径核对 | 是否存在欠费、在途办理、补缴或其他未结事项 |

完整身份信息如为办理所必需，使用官方页面或受限私有文件，不进入 Git、自动化任务正文或公开日志。用户在官方渠道完成登录验证。

执行顺序：读取当前参保名册与在途申请 → 对照变更预览（主体、人员、险种、日期、基数、原因） → 在已明确授权范围内办理 → 记录申请结果 → 独立回查名册与生效月份 → 核对下一期账单是否反映变更。已有明确授权不重复询问；“支持增减员”本身不是给未指定人员办理停保的授权。

提交后超时或结果未知时先查询，不重复提交。受理不等于已生效；减员不等于清偿既往欠费，也不自动撤回当期已在途扣款。各状态分别记录。

## 代扣与定时任务是两件事

先询问用户要哪一种：

| 模式 | 实际执行者与任务作用 |
| --- | --- |
| 官方银行自动代扣 | 用户在官方渠道签署有效协议，由当地税务/银行系统按其规则扣费；AI 周期任务核对账单、协议状态和扣费结果，异常时提醒。创建 AI 任务不会签约或开通代扣 |
| 定时准备，确认后缴费 | 任务先读取真实应缴清单并生成预览，取得对应授权后再由支持的官方渠道办理。仅展示金额不等于扣费 |
| 定时自动申报并发起缴费 | 先验证官方渠道是否支持，并明确主体、期限、费款类型、人员范围、账户协议、金额授权范围及异常规则。未完成这些条件时保留待配置，不能假称已开启自动扣款 |

**推荐优先使用已有官方代扣机制，并定时核对结果。** 这是工程可靠性选择，是否有此机制、支持哪些缴费人必须按当地确认。已经签约也要回查协议生效状态与当期适用范围。

## 建立周期任务前

先补齐并向用户展示可核对的任务定义：

- 明确主体及私有资料目录；任务正文只写别名或私有文件入口，不写证件、密码、令牌和完整银行账号。
- 参保类型、费款所属期如何确定、读取哪个已验证的官方入口。
- 执行模式、当地出账/申报/代扣窗口、首次执行时间、频率和时区。中国经办事项通常使用 `Asia/Shanghai`，不能默用运行电脑的海外时区；仍按用户明确选择。
- 仅查询任务不需要金额扣款授权。涉及实际发起缴费时，明确授权期限和金额范围；超过范围、人员/基数变更、账单差异、登录失效、重复/在途记录时先停在复核状态。
- 正常结果如何记录、何种异常需要提醒；异常提醒是自动化界面设置，不能把“没通知”理解为已缴费。

使用所在助手提供的正式自动化工具建立任务，不把一个本地文件、一段 RRULE 或“以后会提醒”当成创建成功。在 Codex 中通常使用当前线程的 heartbeat；除非用户明确要求独立任务，不另建项目定时任务。先检查已有同主体同用途任务，避免重复创建。调度工具不能表达所需时区/频率时，明确说明并解决后再启用。

用户未给出必要主体、模式或时间时，继续准备资料和任务定义，保留 `未配置`；不能创建一个名称叫“自动扣社保”、实际上只提醒或根本不能登录的任务冒充交付。

## 每次运行的核对顺序

1. 确认当前登录主体与参保地。登录失效或要求验证码时结束本次业务动作，提示用户在官方渠道恢复；不把验证码存作长期凭据。
2. 回查该主体、同一费款所属期和险种的已缴、在途、申报及委托扣款状态。已缴不重复付；在途先等官方结果；读取失败标为未知，不能按“未缴”重试。
3. 核对有效人员与增减员回执、基数、单位/个人部分、应缴金额及官方协议。没有账单不等于没有应缴费。
4. 仅在任务既定执行模式和已有授权范围内继续。失败先查明原因，状态不明确不自动重复发起。
5. 独立回查官方缴费记录，保存脱敏回执引用与时间。记录为 `未操作 / 待处理 / 在途 / 失败 / 官方确认已缴` 中的真实状态；不能凭申请受理、银行余额变化或 AI 任务执行成功宣称已缴。

AI 的金额复核或提醒**不会自动取消银行侧已有代扣**。若要修改/撤销官方协议或阻止在途扣款，必须由有权限的人员按银行/税务实际流程办理，不能承诺本地任务能拦截。

## 与零申报的关系

有员工、工资或社保支出，不能直接推断个体户经营所得的成本费用为零；税额是否为零与社保缴费义务分别判断。先把已发生、已计提、已缴与未缴区分，税前扣除按实际适用规则复核。

不把参保人员增减自动解释为劳动关系合法成立或终止；只按用户真实事实与官方要求办理相关登记。
